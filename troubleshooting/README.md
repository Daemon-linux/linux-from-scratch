# Troubleshooting

This directory documents build failures, unexpected behavior, their root causes, and verified resolutions.

## Issue Report Template

Use the following structure for each significant issue:

1. **Title** — package or component and a short description.
2. **Environment** — host, target architecture, package version, and LFS book section.
3. **Symptoms** — exact error message or failing test.
4. **Investigation** — commands, logs, and evidence used to identify the cause.
5. **Root Cause** — the confirmed cause, or clearly marked hypotheses if not confirmed.
6. **Resolution** — the change made and the exact verification performed.
7. **References** — relevant upstream documentation or related project files.

## Guidelines

- Do not describe a workaround as a root-cause fix unless the cause is understood.
- Keep failed test names and meaningful error output.
- State whether a resolution was verified by rerunning the failing test or build.
- Link to the corresponding build log when available.

The purpose of this directory is to preserve reproducible troubleshooting knowledge, not just a list of commands that happened to work.
